# 无人机编队控制算法（Leader-Follower 与 一致性）

## 一、Leader-Follower（领航-跟随）

### 1. 原理（文字描述）

指定一架无人机为**领航机**，其余为**跟随机**。领航机沿预先规划好的轨迹飞行；每架跟随机以领航机为参照，与领航机保持一个**固定的相对位置关系**（例如"在领航机后方 2 米、右方 2 米、同一高度"），从而整体构成期望队形。

控制上，跟随机实时比较"自己当前的位置"与"领航机位置加上期望相对偏移后的目标位置"，得到位置误差，再用 PID 等控制器去消除这个误差。通常分为两层：外层位置环把位置误差转换为期望速度和姿态，内层姿态环交给飞控执行。领航机保持队形的"基准点"，队形的整体运动由领航机的轨迹决定。

### 2. 需要的无人机传感器

- **定位传感器（自身绝对位置）**：GPS/RTK（室外主力）、IMU（姿态与惯性）、磁力计（航向）、气压计/激光测距（高度）；
- **通信模块（获取领航机位置）**：数传电台 / WiFi / UWB 等，跟随机需实时接收领航机的位置信息（或领航机航迹）；
- **可选（视觉跟随）**：机载相机，通过识别领航机或标记来估计相对位姿（GPS 退化时使用）。

## 二、一致性算法（Consensus）

### 1. 原理（文字描述）

把每架无人机看作通信网络中的一个节点，各机只与自己相邻的几架（邻居）交换状态信息。通过一套**一致性规则**，让所有无人机的某个状态（如位置、速度）逐渐趋向一致；在此基础上，给每架无人机叠加一个不同的**队形偏移量**，就能让它们收敛到"彼此保持期望间距"的队形，而不是挤到同一个点。

与领航-跟随不同，一致性算法**没有固定的中心**：任何一架无人机都只依赖邻居信息，整队通过反复的局部协调逐步收敛到期望队形。收敛的快慢取决于通信拓扑（图是否连通、邻居多少、链路质量）。

### 2. 需要的无人机传感器

- **定位传感器（自身状态）**：GPS/RTK、IMU、磁力计、气压计/激光测距；
- **通信模块（与邻居交换状态）**：数传电台 / WiFi / UWB 等，各机需与相邻无人机双向交换位置/速度信息；
- **拓扑/邻居管理**：需要知道与谁相邻（可预先固定，或按距离动态确定）。

## 三、两种方法对比（详尽）

| 维度 | Leader-Follower（领航-跟随） | 一致性算法（Consensus） |
| --- | --- | --- |
| 控制结构 | **中心式**：以领航机为唯一基准 | **分布式**：无中心，各机平等 |
| 通信需求 | 跟随机只需接收领航机位置（单向为主） | 各机需与邻居双向交换状态，且依赖拓扑 |
| 鲁棒性 | **较弱**：领航机失效/漂移会传导整队，单点故障敏感 | **较强**：单机失效不影响整体，可容错 |
| 可扩展性 | 增加机数只需增加跟随机，但误差可能沿链累积 | 天然可扩展，适合大规模机群 |
| 队形形成方式 | 直接跟踪领航机+偏移，**响应快、无收敛过程** | 通过一致性协议**逐步收敛**到队形，存在收敛时间 |
| 实现难度 | **低**：逻辑直观、参数少 | **中**：需设计一致性协议与通信拓扑 |
| 对数据质量/噪声的敏感性 | 领航机位置误差直接叠加到整队（对**领航机数据质量**敏感） | 各机位置误差经邻居融合，可部分平滑（对**单机噪声**较不敏感，但受通信时延/丢包影响） |
| 队形整体机动 | 由领航机轨迹决定，整体机动方便 | 需要额外的引导信息（如虚拟领导者）才能整体机动 |
| 抗通信时延/丢包 | 领航机信息丢失会退化（较敏感） | 时延/丢包会减慢收敛甚至发散（也较敏感） |
| 适用场景 | 简单编队、队形少变、工程快速落地 | 大规模、分布式、容错要求高的场景 |

### 关键差异小结

1. **依赖关系**：领航-跟随是"一对多"的星形依赖（都依赖领航机）；一致性是"多对多"的邻居依赖（无中心）。
2. **形成机制**：领航-跟随是"直接跟踪"，一致性是"逐步收敛"。
3. **故障特性**：领航-跟随对领航机单点故障敏感；一致性对单机故障鲁棒。
4. **对本方案的启示**：若做平台验证、强调"数据质量 → 队形误差"的因果清晰，**领航-跟随更适合**（误差来源单一、易归因）；若要体现分布式与鲁棒性，则用一致性。

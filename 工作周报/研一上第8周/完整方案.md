# 无人机集群编队维持 —— 完整方案

*王瀚宇 522026320138*

## 1. 场景描述

- **描述**：室外无人机集群（机数任意）按预设队形（直线 / 三角形 / 多边形等）持续飞行，平台运行在**地面边缘机**上（集中式），无人机仅作为"感知 + 执行"终端；平台汇聚并校准各机定位/姿态等数据，去除错误数据，维持队形（阵型）稳定性。本场景是"多机协同吊运"的一个抽象——用平台去错误数据，替代物理耦合对队形的约束。
- **目标**：验证平台对多机定位/姿态数据的汇聚、规约与校准能力，量化其对队形保持稳定性与行为稳定的收益。
- **流程**：队形生成 → 编队起飞 → 各机数据上传边缘机 → 平台规约校准 → Leader-Follower+PID 控制 → 指令下发 → 队形保持 → 降落。
- **可参考项目**：`PX4-Swarm-Consensus-Controller`（ROS2+PX4 一致性）、`MSN-Flocking-Formation-Control`（flocking 集群+避障）、`swarm`（Gazebo 多机编队仿真）。

## 2. 系统组成与职责

| 组成 | 要素 | 职责 |
| --- | --- | --- |
| 物理终端 | 多架四旋翼（机数任意） | 编队飞行、采集数据、执行指令 |
| 边缘机 | 地面边缘计算设备（集中式） | 运行平台与上层控制，集中处理数据并生成指令 |
| 传感器 | GPS/RTK、IMU、磁力计、气压计/激光测距 | 定位、姿态、航向、高度 |
| 执行器 | 各机飞控（位置/速度/姿态） | 执行 Leader-Follower 跟踪 |
| 上层应用 | 队形生成、Leader-Follower+PID 控制器、监控 | 生成期望相对位置并控制 |

**平台**（运行在边缘机上，集中式）在系统中可能起到的作用如下：

1. 汇聚各机定位/姿态/状态数据，与每架无人机建立信道连接；
2. **对（定位、姿态、航向、高度、时间戳）数据进行规约校准，提高数据质量，并校验多机一致性与队形几何约束**；
3. 上传数据/下发指令，整体数据流：

```
各机传感器 →（通信链路）→ 边缘机[平台：汇聚/规约校准] → 上层控制(Leader-Follower+PID)
     ↑                                                                  ↓
     └────────────────────（通信链路）下发指令 ←────────────────────────┘
                              ↓
                          各机飞控
```

即无人机只负责"感知 + 执行"，平台与全部控制算法集中在边缘机上，经通信链路与机群交互。

**技术选型**：Gazebo + PX4 SITL（多实例）、ROS2 Humble + MAVROS（命名空间隔离）、基线算法 **Leader-Follower + PID**、室外 GPS/RTK（仿真加噪）。

## 3. 平台数据规约规则

- **数据源清单**：各机 GPS 位置、速度、IMU 姿态、磁力计航向、高度、时间戳。
- **规约书写方向**：
  - **单条数据**：校验单条记录合法性——位置在任务空域、速度 < 5 m/s、高度 0–120 m、姿态角物理范围、NaN/Inf 检测；
  - **同一传感器数据**：校验时序一致性——时间戳单调递增、相邻帧跳变 < 阈值、噪声水平检测；
  - **同一无人机数据**：校验跨传感器一致性——GPS 与 IMU 变化率一致、气压/测距高度一致、航向与位置航向一致；
  - **整体（多机）**：校验多机一致性——机间距离在安全/几何范围、队形几何约束（期望相对位置）、多机时间同步。
- **校准策略**：越界/失锁/NaN/时间倒退 → **丢弃**；小漂移 → **纠正**（卡尔曼平滑、时间对齐、多源融合）；低置信度 → **标记降级**。

## 4. 噪声来源与注入

| 噪声类型 | 现实来源 / 机理 | 对数据/系统的影响 | 注入方式 |
| --- | --- | --- | --- |
| GNSS 位置噪声 | 多径、遮挡、电离层、接收机噪声 | 机间相对位置错乱、队形发散（最主要） | GPS 话题叠加高斯(σ=1–3 m) + 随机游走 + 失锁(1–5 s) + 多径慢变偏差 |
| IMU 零偏/漂移 | 温漂、老化 | 姿态/位置缓慢漂移 | 角速度/加速度叠加零偏(0.01–0.1 rad/s) |
| 磁力计噪声 | 地磁/电磁干扰 | 航向偏差、方位失准 | 航向叠加噪声(σ 数度) |
| 高度噪声 | 气压/反射面干扰 | 垂直队形偏差 | 高度叠加噪声(σ=5–20 cm) |
| 时间戳错位 | 多机时钟漂移 | 数据对齐错乱 | 错开时间戳(0–50 ms) |
| 通信延迟/丢包 | 无线链路遮挡、干扰 | 一致性/跟踪收敛变慢 | 延迟 50–500 ms、丢包 1–10% |
| 风扰（可选） | 阵风、湍流 | 物理扰动 | Gazebo 风场(0–5 m/s) |

分级：无 / 低 / 中 / 高。

## 5. 对照设计与评估指标

- **对照设计**：A 组接入平台（数据经规约校准后进入控制），B 组不接入平台（数据直连），可能的 C 组不接入平台但采用噪声容忍算法；同机数、同队形、同算法、同噪声脚本，噪声分「无/低/中/高」四级。
- **评估指标**（围绕平台能力组织）：
  - **数据汇聚/中转能力**：多机/多传感器数据汇聚完整性、多机时间同步误差、分发时延；
  - **数据规约与校准能力**：规约校验通过率、错误数据拦截率、校准后定位误差；
  - **队形稳定性（平台能力的最终体现）**：队形保持误差（各机与期望相对位置的 RMS）、机间距离误差、收敛时间；
  - **行为稳定**：轨迹跟踪误差、姿态波动；
  - **任务结果**：队形发散次数、碰撞/退出率；
  - **有序性（借鉴 SOBWOA）**：空间分布一致性、速度一致性、向心朝向。

## 6. 风险（该方案可能的缺点）

- **领航机单点依赖**：Leader-Follower 中领航机失效会传导到整队，需考虑故障处理/重构；
- **边缘机单点依赖**：平台与全部控制集中在边缘机，边缘机故障/算力不足会导致整队失控，需考虑冗余或降级；
- **风扰与数据噪声耦合**：风扰属物理扰动，平台校准无法直接消除，会稀释平台收益，需在实验中将两者分开评估；
- **规约阈值主观性**：机间距离/队形几何约束等阈值需结合队形参数客观设定；
- **通信拓扑影响**：全连接与链式/环式的延迟、丢包影响不同，需明确假设；
- **仿真-真机差距**：GPS 噪声模型需按真实精度标定；
- **结果可能无法体现平台能力**：若队形误差主要由控制器/风扰主导，而非数据质量，平台收益难以分离（需 C 组对照）。

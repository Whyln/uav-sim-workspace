## 一、平台

**定位**：系统中位于 感知端 与 执行端 之间的中间层

**作用**：

1. **数据汇聚 / 中转**：接收来自多个物理实体、多个传感器的数据，统一接入与转发；
2. ==**数据规约与校准**==：按"规约"判断数据合理性，不合理时采取丢弃或纠正策略，保障数据质量；
3. **数据处理与指令下发**：可在其上运行处理逻辑（处理应用），并反向下发指令到飞控/任务；

主要优势：

1. **数据可信**：通过“规约“可以一定程度上减少错误数据的出现，使数据更加准确。
2. **可扩展与可插拔**：支持多物理实体、多传感器、多应用的横向扩展，可统筹管理多执行器的行为。

## 二、应用场景与方案考虑

为了构建一个能充分体现平台能力的无人机应用场景，应重点评估以下因素（判断"平台能力能否被体现"）：

**（一）场景与任务本身**
1. **任务对数据质量的敏感度**：优先"数据即产出"的场景（数据质量直接等于成果质量，如建图）；数据仅作过程（如编队）会稀释校准贡献；
2. **数据源丰富度**：多机、多传感器数据越多，越能体现平台"汇聚、规约"能力。

**（二）数据与规约**
3. **噪声可校准性**：噪声应以"数据噪声"（越界、失同步、离群点，可被丢弃/纠正）为主，而非物理扰动/算法局限；数据噪声占比越高，校准越有效；
4. **规约书写难度 / 自然性**：规约规则应客观易定义（物理范围、几何约束、时间单调），而非主观调参。

**（三）应用层与算法**
5. **应用层是否已解决噪声**：若底层算法已内建抗噪（如鲁棒 SLAM），会掩盖平台价值；需设"噪声容忍算法"对照组分离贡献，或论证平台把抗噪下沉为通用中间层。

**（四）评价与论证**
6. **指标说服力**：有客观、可量化、且与数据质量直接挂钩的指标，能量化平台收益；

7. **因果链清晰度**："数据质量 → 成果精度"因果直接单一；若瓶颈在传感器/算法本身，校准后成果也难提升；

8. **对照可设计性**：能构造"接入平台 / 不接入平台 / 噪声容忍算法"三组对照，分离平台贡献。

   

   所以优先选择"数据即产出 + 多源多机 + 数据噪声为主 + 规约客观 + 应用层未内建抗噪 + 指标客观"的场景。

### 三、初步方案样板

一个初步的场景方案主要思考**是否可行**，**是否体现平台作用**，**是否直观**，包含以下部分

1. 场景描述：描述，目标，流程，可参考项目
2. 系统组成与职责：组成要素和各部分承担的职责，重点介绍平台起到的作用
3. 平台数据规约规则：数据源清单，规约书写方向（单条数据，同一传感器数据，同一实体数据，多实体间等）
4. 噪声来源与注入：现实可能存在的噪声来源，如何注入噪声
5. 对照设计与评估指标：对照实验设计，设计评估指标体现平台能力

6. 风险：方案在实现过程可能遇到的难题

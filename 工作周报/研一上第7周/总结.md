## 二、技术栈

### 2.1 仿真器（AirSim / Gazebo）

- **作用**：仿真器是整套系统的"**物理世界 + 数据源头 + 执行器终端**"。它负责：①提供物理环境（重力、碰撞、场景）；②挂载无人机模型（机身、旋翼、传感器安装位）；③生成传感器数据（相机图像、LiDAR 点云、IMU、GNSS、气压计）；④接收执行器指令（电机 PWM）驱动旋翼、更新物理状态。

- **常见问题**：
  1. **如何搭建环境（教程链接）**：Gazebo 安装https://gazebosim.org/docs/latest/install_ubuntu/)；AirSim https://frendowu.github.io/AirSim-docs-zh/build_linux/)
  2. **如何配置仿真场景**：Gazebo 编写 SDF world 文件（地形/障碍/光照），或用 Fuel 下载现成世界与模型（https://gazebosim.org/docs/latest/sdf_worlds/）；AirSim 用官方预编译场景（Blocks、山景等）或 Unreal 自定义场景（https://frendowu.github.io/AirSim-docs-zh/unreal_custenv/）。
  3. **如何配置仿真无人机（集群）**：AirSim 在 `settings.json` 的 `Vehicles` 数组里声明多架（机型、初始位姿、名称），参考 https://frendowu.github.io/AirSim-docs-zh/multi_vehicle/；Gazebo 在 world 中 spawn 多个无人机模型，各自不同位姿与命名空间。
  4. **如何配置传感器**：AirSim 在 `settings.json` 的 `Vehicles.Sensors` 声明 Camera/Lidar/IMU/GPS/气压计等（https://frendowu.github.io/AirSim-docs-zh/sensors/ 、/lidar/）；Gazebo 在模型的 SDF 里挂 sensor 插件（camera/lidar/imu/gps）。
  5. **AirSim 与 Gazebo 的优劣**：AirSim **视觉逼真**（照片级渲染）、适合视觉感知/合成数据/强化学习，但物理与 ROS/PX4 集成不如 Gazebo 原生、专用 LiDAR（如 Livox 非重复扫描）难以复现；Gazebo 物理仿真强、与 ROS/PX4 **生态紧耦合**、传感器插件丰富，但视觉渲染一般。

### 2.2 飞控（PX4）与地面站（QGC）

- **作用**：PX4负责：①状态估计（EKF2 融合 IMU/GPS/气压，估计姿态/位置/速度）；②姿态/位置控制闭环；③飞行模式管理（外控 OFFBOARD、位置、任务等）；④输出电机混控指令。QGC 是地面站即控制器UI。PX4 位于仿真器与上层应用之间：

  ```
  [仿真器传感器] ──(HIL_SENSOR/HIL_GPS)──► [PX4: 估计+控制] ──(HIL_ACTUATOR_CONTROLS)──► [仿真器电机]
                                               │ MAVLink
                               [QGC(监控/参数/任务)]   [MAVROS → ROS2(上层应用)]
  ```

- **常见问题**：
  1. **如何搭建环境（教程链接）**：PX4 官方仿真文档 https://docs.px4.io/main/zh/simulation/ ；源码 https://github.com/PX4/PX4-Autopilot ；QGC 下载 http://qgroundcontrol.com/ 。
  2. **与 AirSim/Gazebo 的交互**：二者通过 MAVLink 的 HIL 消息闭环——仿真器发 `HIL_SENSOR`（IMU/气压）、`HIL_GPS`（位置/速度）给 PX4，PX4 解算后回 `HIL_ACTUATOR_CONTROLS`（电机指令）驱动仿真器旋翼；Gazebo 经 PX4 的 gazebo 插件、AirSim 经 UDP（14560）连接。
  3. **集群环境需要做出的改变**：每架无人机一个独立 PX4 SITL 实例；各自分配不同 UDP 端口（14540/14550/14560）与 `MAV_SYS_ID`；对应每机独立 MAVROS 与 ROS2 命名空间，避免话题/端口冲突。

### 2.3 应用层（ROS2）

- **作用**：ROS2 是系统的应用层，是实现用户逻辑的地方，通过节点、话题、服务、参数、action 把各模块解耦连接；它承载上层算法（建图/感知/规划）与平台中间层。位于仿真器/飞控之上：

  ```
  [仿真器传感器] ──ros_gz_bridge/airsim_ros──► ROS2 话题 ──► [算法 / 平台中间层]
  [算法 / 平台] ──ROS2 话题──► MAVROS ──► [PX4]
  ```

- **常见问题**：
  1. **如何搭建环境（教程链接）**：ROS2 官方安装 https://docs.ros.org/en/humble/Installation.html ；中文入门 http://dev.ros2.fishros.com/doc/ 。
  2. **与 AirSim/Gazebo 的交互**：Gazebo 用 `ros_gz_bridge` 把 gz 话题桥接为 ROS2 话题、或用 `ros_gz` 包 spawn 模型与交互（https://gazebosim.org/docs/latest/ros2_overview/）；AirSim 用 `airsim_ros` 包把 AirSim 状态/图像发布为 ROS 话题。
  3. **与 PX4 的交互**：经 MAVROS 桥接——订阅 `/fmu/out`（状态上行）、发布 `/fmu/in`（setpoint 指令下行），进入外控（OFFBOARD）模式实现自主控制。

### 2.4 整体框架

1. 传感器数据流

```
仿真器传感器(LiDAR/相机/IMU/GNSS) → ROS2 话题(/scan、/image_raw、/imu、/gps) → 算法(建图/感知)
```

2. 飞控数据流

```
上行(状态)：AirSim/Gazebo → PX4 → MAVROS → ROS2 话题(/fmu/out/vehicle_odometry 等)
下行(指令)：ROS2 控制节点 → MAVROS(/fmu/in/setpoint) → PX4(外控模式) → 电机
```

## 三、平台与工程落地

- **平台接入位置**：插在"传感器 → 算法"（上行，做数据规约校准）”之间
- **噪声注入**：**AirSim**的传感器为理想无噪模型、无内置噪声参数，需在 `airsim_ros` 桥接后的 ROS2 话题层面用噪声节点注入；**Gazebo**传感器插件可配置一定内置噪声参数（camera/imu/lidar），但粒度有限，通常也在 `ros_gz_bridge` 后的 ROS2 话题层面注入；
- **可能的项目结构**：

```
uav-sim-workspace/
├── docs/                       # 周报、方案文档
├── ros2_ws/                    # ROS2(colcon) 工作区
│   └── src/
│       ├── uav_sensors/        # 传感器桥接(ros_gz_bridge/airsim_ros 配置)
│       ├── uav_noise/          # 噪声注入节点(参数化分级)
│       ├── uav_platform/       # 平台中间层(汇聚/规约校准/下发)
│       ├── uav_algorithms/     # 应用层算法
```

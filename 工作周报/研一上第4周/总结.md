## 二、场景选择依据（基于开源项目分析）

对第 3 周文档中各领域的开源项目做横向分析，从"是否依赖传感器数据质量""指标是否可量化""是否有仿真基座"三个维度评估其作为验证场景的适配度：

| 来源领域 | 代表项目 | 技术特点 | 对平台的适配度 |
| --- | --- | --- | --- |
| 测绘 | [Mou-Sa99 …Drone-Swarm…LiDAR…Mapping](https://github.com/Mou-Sa99/Decentralized-Multi-Agent-Drone-Swarm-Framework-for-LiDAR-Based-Exploration-and-Mapping) | AirSim 多机 LiDAR 协同建图 | 高：建图质量直接依赖点云与位姿数据质量 |
| 测绘 | [autonomous-drone-2d-mapping](https://github.com/krushna967/autonomous-drone-2d-mapping) | PX4 SITL + Gazebo + SLAM Toolbox，2D LiDAR 实时建图 | 高：有完整 SLAM 链路，便于注入噪声做对照 |
| 物流 | [autonomous-drone（szebedy）](https://github.com/szebedy/autonomous-drone) | PX4 + Gazebo，SVO2 视觉里程计 + WhyCon 标记定位 + Ewok 规划 | 高：定位质量直接决定投送精度 |
| 物流 | [drone-delivery（leomichalski）](https://github.com/leomichalski/drone-delivery) | ROS + Gazebo + PX4，GPS + ArUco 精准降落 | 高：指标单一直观（投放误差） |
| 物流 | [multi-uav-logistics-gazebo](https://github.com/forest157/multi-uav-logistics-gazebo) | XTDrone 基座，OMPL/TOPPRA/ORCA/MPC，多机配送 | 中高：链路完整，可扩展多机协同 |
| 巡检 | [VTNMPC](https://github.com/open-airlab/VTNMPC-Autonomous-Wind-Turbine-Inspection) | 视觉跟踪 NMPC，贴近贴面对位拍摄 | 中：对姿态/成像质量敏感，但指标偏定性 |
| 巡检 | [drone-inspector](https://github.com/dikshant1103-beep/drone-inspector) | PX4 SITL + ROS2 + YOLO 缺陷检测 | 中：检出率受数据质量影响，但受模型影响耦合 |

**结论**：在"交通勘测"与"运输货物"两个方向中，二者都满足"数据/精度敏感"的要求。其中——

- **交通勘测**属于"**数据即产出**"型任务（产出点云、三维模型、病害清单），数据质量直接等于成果质量，指标最客观、最硬，且与文档中的测绘/建图类开源项目直接衔接；
- **运输货物**属于"**任务即结果**"型任务（投放是否精准、是否成功），指标直观但相对单一。

因此本方案**以"交通勘测"为主场景**，并在末尾给出"运输货物"作为可选的补充/对照场景，形成"数据型 + 任务型"双重验证，使平台价值体现得更充分。

## 三、目标场景定义

**场景名称**：面向交通基础设施（公路 / 桥梁）的无人机勘测仿真场景

**任务描述**：无人机沿道路走廊 / 桥面自主航测，搭载激光雷达与下视相机，同步采集点云与影像，经建图与处理生成道路三维模型、DEM/正射影像，并识别路面病害（裂缝、车辙、坑槽等），最终产出勘测数据与病害清单。

**场景要素**：

- **输入**：仿真交通环境（道路走廊 / 桥面世界）+ 可控感知噪声（LiDAR 测距噪声、GNSS 漂移、图像噪声、风扰）；
- **过程**：自主航线飞行 → 多传感器同步采集 → SLAM 建图与定位 → 三维重建 / 病害识别；
- **输出**：点云地图、DEM / 正射、病害清单，以及数据质量与行为稳定性指标；
- **平台角色**：
  1. **数据质量保障**——时间同步、去噪与离群点剔除、丢帧/失锁检测与恢复、多源一致性校验；
  2. **行为稳定性监控**——位姿/速度/悬停误差监控、姿态波动与振动分析、异常检测与告警。

## 四、该场景适合验证平台的理由

1. **数据即产出**：勘测成果完全由采集数据决定，数据质量可无损地传导到成果精度；
2. **噪声高度敏感**：位姿漂移、点云噪声、图像模糊会直接导致点云错层、模型畸变、病害漏检；
3. **指标客观可量化**：空三残差、点云 RMSE、DEM 误差、病害检出率、投放/定位误差等；
4. **有开源基座可复现**：可基于文档中的 PX4 SITL + Gazebo + SLAM 类项目快速搭建，噪声可注入、实验可重复。

## 五、技术方案

### 5.1 仿真环境与运行基座

- **飞控与仿真**：PX4 SITL + Gazebo（Harmonic）+ ROS2，参考 `autonomous-drone-2d-mapping` 的集成方式（MAVROS / ros_gz_bridge / SLAM Toolbox）；
- **可选多机扩展**：参考 `multi-uav-logistics-gazebo`（XTDrone 基座）与 `Mou-Sa99` 的多机建图框架；
- **世界搭建**：自建道路走廊世界（路面、车道线、护栏、桥梁构件、路灯），可用 Blender 建模后导出为 SDF，参考第 3 周文档中洪涝监测项目"Blender + GIS 建世界"的做法；
- **载荷建模**：2D/3D LiDAR + 下视相机；如需视觉/多机扩展，可切换至 AirSim（参考 `Mou-Sa99`）。

### 5.2 导航与建图

- **定位与建图**：激光/视觉惯性 SLAM（SLAM Toolbox、FAST-LIO 等），输出位姿与占据栅格 / 点云地图；
- **航线规划**：道路走廊覆盖式航线（带状/割草式），可复用覆盖规划思路（参考覆盖路径规划类工作）；
- **避障**：ORCA / MPC（参考 `multi-uav-logistics-gazebo`），用于桥下、护栏等受限空间。

### 5.3 数据质量保障机制（平台核心一）

- **时间同步与对齐**：多传感器时间戳对齐、外参标定校验；
- **去噪与滤波**：点云离群点剔除、地面点滤波、图像去噪；
- **异常检测**：丢帧率、数据中断、定位失锁检测与恢复；
- **一致性校验**：多源（LiDAR / 相机 / IMU / GNSS）交叉验证，标记低置信度数据。

### 5.4 行为稳定性监控（平台核心二）

- **飞行状态监控**：位置/速度/悬停误差、姿态角波动、轨迹跟踪误差；
- **稳定性分析**：振动与姿态抖动统计、超限告警；
- **闭环干预**：异常时触发悬停/重飞/接管，保证采集过程稳定。

### 5.5 噪声注入设计

| 层级 | 噪声类型 | 注入方式 |
| --- | --- | --- |
| 传感器 | LiDAR 测距噪声、点云离群点、视场遮挡 | 在 Gazebo 传感器插件或数据后处理中叠加 |
| 传感器 | 相机高斯噪声、运动模糊、曝光抖动 | 图像处理环节叠加 |
| 导航 | GNSS 漂移 / 短时失锁、IMU 零偏 | 修改仿真定位话题或引入偏差 |
| 环境 | 风扰、光照变化 | Gazebo 风场插件、光照参数 |

按**无 / 低 / 中 / 高**四级设定噪声强度，形成递进的退化条件。

### 5.6 对比实验设计

- **分组**：A 组接入平台 vs B 组不接入平台，各自跑遍四个噪声等级（2 × 4 共 8 组）；
- **控制变量**：相同场景、相同航线、相同噪声脚本、相同建图算法，仅"是否接入平台"不同；
- **评价指标**：

| 类别 | 指标 |
| --- | --- |
| 数据质量 | 时间同步误差、丢帧率、点云密度/噪声水平、位姿估计误差 |
| 行为稳定性 | 悬停位置偏差、姿态角波动、轨迹跟踪误差 |
| 成果精度 | 点云 RMSE、DEM/正射精度、病害检出率、定位误差 |

- **预期结论**：随噪声增强，B 组指标迅速退化，A 组退化显著更缓——以此量化平台对"数据质量保障 + 行为稳定性"的价值。

## 十、开源项目深入分析（逐项目）

> 以下按第 3 周文档中的各领域开源项目逐一展开，分析其**具体场景、目录结构、传感器配置及作用**，并标注与“数据质量保障 + 行为稳定性监控”平台的关联点。

### 10.1 VTNMPC（风机巡检）

- **具体场景**：在 PX4 SITL + Gazebo 中，无人机（DJI M100 机型）绕风机叶片自主巡飞，由“时间最优图搜索全局规划 + 视觉跟踪 NMPC”输出姿态角速率与推力指令，使无人机始终以最佳朝向、入射角与距离贴近叶片拍摄；支持注入风扰仿真。
- **目录结构**：`WTI_catkin`（catkin 工作空间）内含 `dji_m100_trajectory`（航线与全局规划，含 `GP_statemachine`、`windgen_recdata.launch`）、`quaternion_point_traj_nmpc`（NMPC 控制器）；`WTI_px4_modified`（修改版 PX4 SITL）+ `shell_scripts/run_sitl_gazebo_withWrapper_terminator.sh`；规划器输出“巡检点 + 表面法线”的 txt 供 NMPC 使用。
- **传感器配置与作用**：机载相机（视觉跟踪叶片表面，用于估计相对位姿与保证成像质量）+ 飞控 IMU/状态反馈（NMPC 闭环）。无独立 LiDAR。
- **平台关联点**：视觉跟踪数据质量与位姿稳定性直接决定拍摄质量；风扰场景下正是“行为稳定性监控”的天然试验台，可注入视觉噪声与风场验证平台收益。

### 10.2 drone-inspector（仓库巡检）

- **具体场景**：Gazebo Classic 11 的 EV 电池货架仓库世界中，PX4（iris + FPV 相机）以 20 Hz OFFBOARD 流按航线自主巡检，飞行中 YOLO 实时检测缺陷，降落后由本地 VLM（Qwen2.5-VL）复核并生成 PDF 巡检报告，全程由浏览器控制台操控。
- **目录结构**：`control/drone_controller.py`（MAVSDK 控制器，持续 20 Hz 设定点流 + 发散保护）、`world/`（`layout.py` JSON↔SDF、`scene_client.py` 实时增删模型）、`vision/`（`camera_capture`、`defect_detector`、`visual_analyst`）、`agent/`（LLM 任务智能体）、`report/`（PDF 生成）、`simulator/worlds/`（warehouse.world）、`ros2_ws/src/camera_bridge/`（`camera_node`、`scene_node`、`bridge_all`）、`dashboard/`（FastAPI + hub + 前端）。
- **传感器配置与作用**：机载 FPV 可见光相机（缺陷检测与复核的画面来源）+ MAVSDK 遥测（位姿、电量，用于航线跟踪与安全）。
- **平台关联点**：图像丢帧/模糊直接影响检出率；位姿数据质量影响航线精度与缺陷定位；项目自带“发散保护”，可与平台的行为稳定监控对照。

### 10.3 TASBID（桥梁巡检训练）

- **具体场景**：Unity 开发的桥梁检测训练与考核系统，受训者用键盘/手柄操控伴随无人机完成 4 类检测任务，系统提供任务中提示与任务后绩效评估；后续版本增加自主模式（F1–F4）与语音指令控制。
- **目录结构**：仓库仅含 `README.md`、`TASBID Manual.docx` 与 `UAV_inspection_final_version_...unitypackage`（无人机控制代码被隐藏，需另行购买商业插件）；依赖 Road Architect、unity-traffic-simulation 等资产。
- **传感器配置与作用**：无人机相机视角（可见光）+ 灯光开关，均为虚拟；无物理传感器数据。
- **平台关联点**：属人因/训练类仿真，不涉及传感器数据质量；但其“巡检视角与拍摄标准”可为主场景的成像规范提供参考。

### 10.4 Mou-Sa99 多机 LiDAR 建图（测绘）

- **具体场景**：AirSim（UE4.27）中多机协同三维结构建图——侦察机（Scout）探索、检测障碍、闭合边界并标记结构；测绘机（Mapper）依据标志分层建图；结果写入共享地图。
- **目录结构**：`Swarm_Control/scout_drone/`（`Obstacle_Detector`、`Perimeter_Mapper`、`Point_cloud_sorter`、`Scout_Drone`、`Write_to_JSON`）、`Swarm_Control/Mapper_drone/`（`Mapper_Drone`、`Mapper_Drone_assembly`（垂直 5 m 布放）、`Surface_Tracer`）、`shared_map/`（`global_map.ply`、`scout_drone.ply`、`structure_flags.json`、`visualizer`）。
- **传感器配置与作用**：LiDAR（测绘机采点云建图；侦察机以 LiDAR 扫描做障碍/边界检测）；点云以 `.ply` 共享，标志以 `.json` 传递。
- **平台关联点**：LiDAR 噪声/丢帧直接劣化建图精度；多机共享地图要求位姿与时间一致，是平台“数据质量保障”的典型对象。

### 10.5 autonomous-drone-2d-mapping（室内 2D 建图）

- **具体场景**：PX4 SITL + Gazebo Harmonic 的自建室内世界中，无人机以 2D LiDAR 自主巡飞并实时构建占据栅格地图。
- **目录结构**：`odom_flatten/`（`px4_odom_flatten_node.cpp`，处理 PX4 里程计）、`worlds/indoor_room.sdf`、`scripts/`、`docs/`、`images/`；工作流为启动 PX4 SITL → Gazebo 时钟桥 → LiDAR 话题桥接 → `/scan` → MAVROS → 静态 TF → 里程计拉平 → SLAM Toolbox → RViz。
- **传感器配置与作用**：2D LiDAR（扫描环境生成栅格地图，配合 SLAM Toolbox 提供定位与建图数据）。
- **平台关联点**：链路最简洁、组件最少，是**注入 LiDAR 噪声做对照实验的最佳基座**；`odom_flatten` 表明里程计数据需处理，正对应平台的数据质量环节。

### 10.6 Airsim-UAV-SAR-Yolov5（海上搜救）

- **具体场景**：在 AirSim 中执行无人机海上搜救，机载识别落水/待救目标。
- **目录结构**：仓库仅有简要 README（描述性项目，无完整工程结构）。
- **传感器配置与作用**：AirSim 机载相机（视觉），影像输入 YOLOv5 完成目标识别。
- **平台关联点**：图像质量决定检出率；项目较简，可作为“视觉感知 + 噪声”对照的轻量示例。

### 10.7 monitoring-flood（多机洪涝监测）

- **具体场景**：Gazebo 中 17 架无人机（16 架检测 + 1 架俯瞰录像）协同搜索未知区域洪涝；采用 FATII 自适应控制、基于图像分割的判洪算法与 CVT 区域分配。
- **目录结构**：`flood_monitor_16/launch/`（16 个 `droneXX.launch` + `flood_monitor.launch`、`world.launch`）、`src/`（`controller.py`、`drone01–16.py`、`drone_monitor.py`、`config.ini`、`drone_position.csv`、`images/`）、`worlds/`（`world01–05.dae/tif/world`、`material/blue_plane` 水面材质、`models/launch_pad`）、`hector_quadrotor/`（含 `quadrotor_downward_cam_red` 下视相机模型）。
- **传感器配置与作用**：机载**下视相机**（16 架，图像分割判定淹没区域）；另 1 架用于俯瞰记录。世界由 Blender + GIS 建模后导入。
- **平台关联点**：分割结果完全依赖图像质量；多机协同对位置与时间一致性敏感，可验证平台的数据保障与行为监控。

### 10.8 MultiAgent-SAR-System（集群搜救）

- **具体场景**：面向复杂非结构化环境的无人机集群协作搜救仿真（自研 Python 平台），含涡旋势场避障、分布式 Voronoi 覆盖 + 信息熵地图、Lévy 飞行搜索、异构角色（侦察/确认/支援）、基于拍卖的任务分配，遵循 OODA 架构。
- **目录结构**：`src/`（`vortex_field`、`drone_agent`、`coordinator_agent`、`agent_base`、`algorithms`、`advanced_algorithms`、`communication`、`environment`、`scenarios`）、`simulation.py`、`run_experiments.py`、`plot_results.py`、`figures/*`、`experiment_results.json`。
- **传感器配置与作用**：**无实体传感器**——以概率感知模型（视场角、距离衰减、视线遮挡）模拟传感器特性，作为搜索决策输入。
- **平台关联点**：其概率感知模型可直接映射为“感知噪声/数据质量下降”，但整体为抽象多智能体仿真，非物理级飞控仿真。

### 10.9 anti_drone_agc_workspace（反无人机空地协同）

- **具体场景**：基于 ROS 的反无人机空地协同实验平台，集成 A-LOAM SLAM、LQR 轨迹跟踪（直线/圆周/螺旋/8 字/悬停）、扇区规则避障与 DQN 局部避障（Dueling + Double + 优先经验回放），并提供**实验日志与六项评价指标**。
- **目录结构**：`src/`（`A-LOAM`、`air_ground_core` 地面平台、`drone_launch_controller`、`lqr_trajectory_tracker`、`rl_obstacle_avoidance`、`gazebo_ros_pkgs`、`velodyne_description/gazebo_plugins/simulator`）、`scripts/`（`start_sim.sh` 四种模式、`analyze_trajectory.py`、`evaluate_experiment.py`）、`docs/`（指导书、`dqn_training.md`、`learning_plan.md`）、`experiment_data/*.csv`、`training_runs/`。
- **传感器配置与作用**：Velodyne 3D LiDAR（VLP-16/HDL-32/HDL-64，用于 A-LOAM 建图与感知）+ PX4 飞控 IMU/GNSS（位姿）；机型 `iris_3d_lidar`。
- **平台关联点**：**已内置实验日志与量化评价**，与平台“行为稳定性监控”高度契合；3D LiDAR 噪声 → SLAM 退化是现成的对照实验。

### 10.10 PX4-Iris-Drone-Path-Planning-CV（植保勘测）

- **具体场景**：Gazebo 中 PX4 Iris 自主路径规划与避障，在航点用相机拍照，以 YOLOv8 分割杂草并生成杂草密度热力图，服务农田勘测。
- **目录结构**：`Path_planning/`（轨迹与航点图）、`Simulation/`（仿真截图）、`Weed_detection/`（`downward_camera.png`、`runs/detect/predict/...`、`heatmap_eg_3.png`）；无人机挂载 camera plugin。
- **传感器配置与作用**：机载**下视相机**（航点拍照用于杂草检测）+ 仿真位姿（航线跟踪与避障）。
- **平台关联点**：图像质量决定检测与热力图准确性；航点定位与姿态稳定决定覆盖完整性——与主场景（勘测）逻辑一致，可作为轻量预演。

### 10.11 autonomous-drone（szebedy，自主投送）

- **具体场景**：基于 Intel Aero + PX4 的自主包裹投送，可在真机或 Gazebo 仿真运行；核心为 ROS 节点，经 MAVROS 与 PX4 通信，使用 SVO2 视觉里程计、WhyCon 视觉标记定位与 Ewok 避障轨迹规划（附 ICUAS 2019 论文）。
- **目录结构**：`src/offboard_control/`（`drone_control.cpp`、`ros_client.cpp`、`main.cpp`，`launch/simulation.launch`、`intel_aero.launch`）、`src/trajectory_planner/`（`ewok/*` 多项式/B 样条优化、`trajectory_planner.cpp`）、`src/whycon/`（圆检测、`localization_system`、`launch/whycon.launch`、`patterns/circle.pdf`）、`src/usb_cam/`（相机驱动）。
- **传感器配置与作用**：**单目相机（usb_cam）**同时承担视觉里程计（SVO2）与标记识别（WhyCon）——是定位与目标识别的唯一数据源。
- **平台关联点**：无 GPS 依赖、全凭视觉，对图像质量、曝光、时间同步极敏感；注入图像噪声/丢帧即可显著体现平台的数据保障价值，是**“数据质量敏感型”首选参照**。

### 10.12 drone-delivery（leomichalski，精准投送）

- **具体场景**：GPS + ArUco 视觉标记的自主包裹投送：GPS 导航飞抵投放点，机载相机识别 ArUco 标记完成精确降落；支持真机（树莓派 companion）与 Gazebo 仿真（ROS Noetic + Gazebo 11 + PX4 1.13）。
- **目录结构**：`vision/`（`arucodetector.py`、`videosourcegazebo/pi/zmq`、`bridgeros/zmq`、`videostreamingapp`、`topics`、`msgs`）、`flight/aruco_hunter/`（`src/main.cpp`、`launch/main.launch`、`scripts/generate_mission_waypoints.py`、`transition_diagrams`）、`flight/aruco_msgs/`（`ArucoDetection.msg`）、`scripts/`（树莓派与镜像工具）。
- **传感器配置与作用**：机载相机（ArUco 检测，末端精确定位）+ GPS（粗定位与导航）。
- **平台关联点**：投送误差由“GPS + 末端视觉”数据质量共同决定；注入 GNSS 漂移与视觉识别噪声即可量化平台收益，指标直观（投放误差、成功率）。

### 10.13 multi-uav-logistics-gazebo（多机物流配送）

- **具体场景**：三机物流配送 Gazebo/PX4/ROS 仿真，含 OMPL 三维规划、TOPPRA 时间参数化、ORCA 局部避障（动态 TTC、风险迟滞）与影子模式分布式 MPC；支持包裹投递、动态障碍（飞鸟/交叉）、电量评估与返航、安全互锁。
- **目录结构**：`catkin_ws/src/logistics_gazebo_sim/`——`config/`（多套 `mission_sceneX.yaml`、`dynamic_obstacles_*.yaml`）、`launch/`（`three_uav_mission`、`operator_station`，以及能量/感知陈旧/安全互锁/轨迹连续性等**专项试验** launch）、`models/iris_3d_lidar`、`scripts/`（`offboard_controller`、`dynamic_avoidance_planner`、`lidar_cloud_aggregator`、`lidar_dynamic_detector`、`parcel_delivery_manager`、`perception_acceptance_matrix`、`perception_visualizer`、`fleet_*` 监控、`energy_*`）、`src/logistics_gazebo_sim/`（`formation_3d`、`formation_scheduler`、`local_avoidance`、`pointcloud_perception`、`perception_acceptance`、`safety_interlock`、`target_tracking`、`track_metrics`、`error_model`、`scenes`、`worlds`）、`src/ompl_3d_planner.cpp`、`test/`（67 项回归测试）。
- **传感器配置与作用**：**iris_3d_lidar（3D LiDAR）**→ 点云感知（`pointcloud_perception`、`lidar_cloud_aggregator`、`lidar_dynamic_detector`）；飞控位姿→队形与投送；能耗模型→返航决策。
- **平台关联点**：**与平台契合度最高**——已具备 `perception_stale_trial`（感知陈旧试验）、`safety_interlock`、`track_metrics`、`error_model` 等模块，可直接作为“数据质量 + 行为稳定性”验证的**首选基座**。

### 10.14 mavsdk_drone_show / MDS（机队与灯光秀）

- **具体场景**：PX4 机队操作栈（v5.5），覆盖无人机灯光秀（导入 SkyBrush 轨迹并同步执行）、Smart Swarm（leader-follower 协同）、QuickScout SAR 覆盖规划，以及 SITL/GCS 服务、React 操作台与遥测日志；另含 Simurgh LLM 操作员（beta，需人工确认）。
- **目录结构**：`docs/guides/`（SITL、Simurgh、GCS、MDS Init）、`docs/features/`（drone-show、smart-swarm、swarm-trajectory）、`assets/brand/`、`CHANGELOG.md`、`LICENSE`（PolyForm）。
- **传感器配置与作用**：定位模块（GPS/RTK，用于编队同步与安全间距）、遥测与 ULog 日志（行为记录与复盘）；灯光秀由 LED 载荷呈现。
- **平台关联点**：强调**遥测证据链与可复盘日志**，与“行为稳定性监控”直接对应；RTK/时钟一致性是编队安全前提。

### 10.15 clever-show-ds（多机灯光秀仿真）

- **具体场景**：多机 Clover 灯光秀仿真，每架无人机以独立 Docker 容器运行“PX4 SITL + Clover + clever-show”栈，可选 jMAVSim 或 Gazebo，数量按性能扩展。
- **目录结构**：`simulate.py`（启动参数 -n/-p/-d/--headless）、`Dockerfile`、`gazebo/`（`gazebo.launch`、`single_vehicle_spawn.launch`、`worlds/empty.world`、`models/`（asphalt_plane、rotors_description iris）、`plugins/libgazebo_gps_plugin`、`libgazebo_imu_plugin` 等）、`services/`（`clever-show@.service`、`show-starter.service`、`visual_pose_watchdog.service`）。
- **传感器配置与作用**：仿真 GPS/IMU 插件（提供定位与姿态）；视觉定位由 Clover 视觉系统在仿真数据上模拟。
- **平台关联点**：多机协同与 `visual_pose_watchdog`（视觉位姿看门狗）与平台监控直接相关；README 指出 jMAVSim 模式下各机“各自世界、互不知碰撞”，正说明**多机数据一致性**的重要性。

### 10.16 clever-show（Clover 灯光秀软件）

- **具体场景**：基于树莓派 + Clover + PX4 的无人机灯光秀：在 Blender 中制作动画、一键导出机队航迹，室内用光流/ArUco、室外用 GPS 定位执行演出（剧场 12 机实演）。
- **目录结构**：`blender-addon/`（动画导出）、`drone/`（`client.py`、`failsafe.py`、`modules/`：`animation`、`client_core`、`flight`、`led`、`mavros_wrapper`、`tasking`）、`server/`、`builder/`（镜像构建、`clover-config` 含 `camera_info/calibration.yaml`、`launch/aruco.launch`、`led.launch`、`map/animation_map.txt`）、`examples/`（`animations/basic`、`figures`、`chrony` 时间同步配置、`fcu_parameters`、`positioning/aruco floor`、`gps`）。
- **传感器配置与作用**：定位系统（室内光流 / ArUco 地图、室外 GPS）+ 相机（ArUco/光流定位）+ LED 载荷；`chrony` 提供多机时间同步。
- **平台关联点**：定位质量与**时钟同步**是编队安全的核心，`examples/positioning` 与 `chrony` 提供了标准配置，可直接借鉴为平台的数据质量基线。

### 10.17 skybrush-server（CollMot 灯光秀服务端）

- **具体场景**：Skybrush 生态服务端，负责与无人机通信的抽象层，向 Skybrush Live 等前端屏蔽机型差异；同时提供时钟、RTK 校正源、天气等设施，可通过扩展模块动态加载。
- **目录结构**：`etc/conf/`（indoor/outdoor/virtual 多套 jsonc 配置）、`etc/deployment/`（docker、rpi：`network.cfg`、`skybrush.json`、`ufw.conf`、开机任务）、`src/flockwave/server/`（`comm.py`、`commands`、`command_handlers/`：calibration/color/parameters/version、`ext/`：`clocks.py`、`beacon`、`crazyflie/`（connection、driver、fence、`led_lights`、`mocap`、`scanning`、`trajectory`）、`auth*`、`auto_shutdown`、`connection_limits`、`console_status`、`ext_manager` 等）、`gateway/`、`proxy/`。
- **传感器配置与作用**：RTK 校正源（定位精度）、时钟（多机时间同步）、天气数据；Crazyflie 扩展含动捕（mocap）与 LED/轨迹能力。
- **平台关联点**：**时钟与 RTK 一致性正是“数据质量保障”的经典体现**；其以扩展模块统一管理多源数据的架构，可作为平台数据质量模块的设计参考。

### 小结：项目 → 平台能力映射

| 平台能力 | 最相关的参考项目 |
| --- | --- |
| 传感数据质量保障（时间同步、去噪、一致性） | skybrush-server、clever-show（chrony/定位）、multi-uav-logistics-gazebo（perception_stale）、autonomous-drone-2d-mapping |
| 行为稳定性监控（位姿/轨迹/异常） | anti_drone_agc_workspace（实验日志+指标）、multi-uav-logistics-gazebo（track_metrics/safety_interlock）、mavsdk_drone_show（遥测/ULog） |
| 视觉数据质量敏感（噪声对照） | autonomous-drone（SVO2/WhyCon）、drone-delivery（ArUco）、drone-inspector、monitoring-flood |
| 激光数据质量敏感（噪声对照） | autonomous-drone-2d-mapping、anti_drone_agc_workspace、Mou-Sa99 多机建图 |
| 仿真基座可复现 | multi-uav-logistics-gazebo（XTDrone）、autonomous-drone-2d-mapping（PX4+Gazebo）、clever-show-ds（Docker 多机） |
